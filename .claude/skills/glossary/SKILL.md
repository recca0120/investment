# 名詞解釋與寫文章時的名詞核對

使用者是股市新手。文章裡第一次出現的名詞會自動變成名詞小卡（點了在原地看解釋），所以**名詞解釋有沒有收這個詞、文章用的是不是同一個名稱**，直接決定新手看不看得懂。

以前靠手動核對，漏過：文章 02 的「三基金組合」沒有名詞解釋（名詞解釋自己還引用它）、文章寫「股債配置」但名詞解釋叫「股債比」——兩個都沒有小卡，新手還會以為是兩件事。這份 skill 的工具就是用來一次看清楚，不用再一個一個查。

## 工具：scripts/terms.mjs

```bash
node .claude/skills/glossary/scripts/terms.mjs list                       # 依分類列出所有名詞和「一句話」
node .claude/skills/glossary/scripts/terms.mjs check docs/knowledge/02-recommended-methods.md
node .claude/skills/glossary/scripts/terms.mjs check --all                # 全部知識文章（CI 也會跑）
```

`check` 用的是網站真正的 Markdown 外掛（`site/plugins/markdown.mjs`），所以「會連成小卡」的清單和網站上看到的一致。報告：

| 記號 | 意思 | 怎麼處理 |
|---|---|---|
| 會連成小卡 | 網站上會有小卡的名詞，依第一次出現的順序 | 確認重要的名詞都在裡面 |
| ✗ 用了別名 | 文章用的說法和名詞解釋不同（別名表 `docs/glossary/aliases.json`） | 改成名詞解釋的正式名稱。結束碼 1，CI 會擋 |
| ✗ 沒資訊的標題 | 「注意」「補充」「共同點」「結論」「XX 介紹」這種只看標題得不到結論的 | 改成寫出結論（決策 0006）。結束碼 1 |
| ? 可能要補進名詞解釋 | 「」裡的詞、粗體短詞、代號，名詞解釋裡沒有 | 自己判斷，見下面「要不要補」 |
| ? 讀者看得到但不會有小卡 | 名詞只出現在標題、引言、連結文字裡（網站不在這些地方放小卡） | 在正文裡自然地提到一次，讓它有小卡 |

## 寫文章的流程

1. **寫之前**：跑 `list`，用名詞解釋裡的名稱寫。需要的概念不在清單裡，先記下來，等等補
2. **寫**
3. **寫完**：跑 `check <文章>`，把 ✗ 全部改掉，逐條看 ?
4. **補名詞**（需要的話，格式見下面），再跑一次 `check`，確認新名詞出現在「會連成小卡」
5. **送出前**：`check --all` 和 `npm run test:site`（`tests/site/skills/glossary-terms.test.ts` 會跑 `check --all`）

## 要不要補進名詞解釋

問自己：**新手讀到這個詞，會不會停下來想「這是什麼」？**

- 要補：投資、金融、稅務用語（三基金組合、累積型、緊急預備金）、商品代號（VTI、00679B）、方法名稱
- 不用補：一般中文（最慘的時候、流程）、強調用的粗體句子、本 repo 的功能名稱（回測器、持股追蹤）、工具和服務名稱（FinMind、LLM）
- 不是名詞但一直被列出來：加進 `docs/glossary/aliases.json` 的 `$ignore`，下次就不會再出現
- 同一件事有其他常見說法（股債配置／股債比）：正式名稱當名詞解釋的標題，其他說法加進 `aliases.json`，文章一律用正式名稱

## 新增一個名詞

1. 選分類（`docs/glossary/` 的六頁）：帳戶與交易、商品類別、常見代號、報酬與風險、策略、成本與稅
2. 照固定格式寫，四項都要有（網站的名詞小卡取「一句話」和「新手注意」，測試會檢查四項）：

   ```markdown
   ### 三基金組合

   **一句話**：用三檔 ETF 分別買美國股票、美國以外股票、債券，再自己決定比例。

   - **用途**：……
   - **例子**：……
   - **新手注意**：……
   ```

3. 標題只寫名詞本身：標題就是網址錨點，改名會讓舊連結失效
4. 一句話用白話，新手看得懂；有數字要附日期和來源（頁尾「資料來源」）
5. 跑 `check`：新名詞要出現在用到它的文章的「會連成小卡」裡

## 為什麼名詞小卡只在某些地方出現

網站的規則（`site/plugins/rehype-glossary-links.mjs`）：

- 每篇文章每個名詞只連**第一次出現**的地方；長的名詞優先（「市值型 ETF」先於「ETF」）
- 不連：標題、引言、程式碼、已經是連結的文字、手機上會藏起來的表頭、「資料來源」之後
- 只處理 `docs/knowledge/` 的文章

所以改一句話就可能讓小卡換位置或消失——改完都要跑 `check`。
